# Demo app

A developer runs a Vite + React page for the Camellia showcase. Pill links at the top switch among Blocks, Tokens, and Pipeline. Blocks is a masonry of components. Each card is the component at its resting size, scaled down evenly when that is what lets the feed use more columns. Hovering or focusing a card shows the component name and a button that opens its details. Below 640px the masonry is a single column of full-width cards, and the details panel is not on the page until a card opens. The details view is a dialog. At 640px and wider the card moves to one shared size and a panel sits beside it. On a tighter desktop or tablet width the card frame scales down to fit, and the panel keeps a readable minimum width. Below 640px the card pins to the top at one shared height, the component scales evenly, and the panel fills the rest of the screen down to the bottom inset. That choice follows the viewport width only. A coarse pointer, a missing hover, or a touch screen does not switch the layout. After it opens, the title row stays pinned and the description and controls scroll together beneath it. The page underneath stays put, including on a phone, and closing restores the previous scroll position. Blocks ships three components: a security-code generator with six split-flap reels that rest on HELLO! until the round button, whose fill is the countdown, the proximity hex color picker, and a guide feedback card. The card asks how clear the guide was. A rating from 1 to 5 opens optional reasons and a comment. Submit replaces the form with a one-line receipt. Each Reset control is quiet text on the same row as the Controls heading. Tokens lists the generated custom properties and switches light and dark. Pipeline holds a short placeholder. Typography renders in Geist and Geist Mono, which the page loads. The demo sets grayscale font smoothing once on `body` in `src/styles/global.css`, so text on macOS draws slightly thinner. Component stylesheets do not set it. The page is not part of the token pipeline roadmap.

## Sub-features

- `demo-dev` serves the page locally with hot reload.
- `demo-build` produces a production build in the root `dist/`.
- `demo-nav` switches among Blocks, Tokens, and Pipeline from pill links. The current link is the same weight in the primary text color. A pointer hover uses the subtle surface. The focus ring shows for the keyboard only.
- `demo-masonry` lays the cards out in equal-width columns, up to three, choosing the most columns whose content stays at least three quarters of its resting width inside the card padding. A scale below 1 tightens that inline padding. Below 640px there is one column and no feed scale. A card's height comes from that scaled content, stays put while the component changes state, and opening one does not reflow the grid. The sticky bar stays above the feed, including a raised selected color cell.
- `demo-details` opens a component's details from its icon button, traps focus, and closes from Escape, the scrim, or the Close button, returning focus to the button that opened it. The dialog title receives focus and does not show a ring. Keyboard focus inside the dialog still shows a ring. At 640px and wider the panel sits beside the card. Below 640px the card stays pinned, the panel title stays pinned, and the description and controls scroll together. Closing restores the page scroll.
- `demo-theme` switches the Tokens page between light and dark.
- `demo-picker` shows the proximity hex color picker inside its card. Its details panel has Radius, Scale, and Darken controls. Darken starts at 0. Reset is text on the Controls row and restores those values. On a coarse pointer, a horizontal drag on a slider changes its value and a vertical drag scrolls the panel body.
- `demo-code` shows the security code. Six reels rest on HELLO! until the person activates the round button. The code is 6 digits from `crypto.getRandomValues`. This is a demo, not a one-time password. Nothing spins on load. Fill style is Smooth or Retro. Smooth is the default: the graphite fill grows left to right across Countdown, from 3 to 30 seconds, default 30. Retro jumps from empty to full across 3 seconds. Countdown stays in the list and is disabled while Retro is selected. When the time ends, the reels flip back to HELLO! and the button returns to the create icon. Reset restores Smooth, 30 seconds, and the HELLO! resting state. The button is the small control size, shorter than one reel. Its fill paints the whole button, including the rounded ends, with no light gap when the graphite is complete. While the reels move, the button is a greyed-out create icon and stays focusable. Pressing it scales the visual to 0.97 from the center, then eases it back to 1. The greyed button stays at scale 1. It shows neither a percent nor a seconds count. A polite live region announces the new code, then Copied, then "Code expired. Create code."
- `demo-feedback` shows the guide feedback card. It fills the card's content width. The scale starts with no rating. A pointer choice fills one segment at a time. Arrow keys, Home, End, and the number keys 1 through 5 choose at once and open the reasons. Add a comment reveals the field and moves focus there. Submit shows a one-line receipt with Edit for 6 seconds. Edit puts the same rating, reasons, and comment back and focuses Submit. Cancel and Escape clear the response. Escape does nothing while the comment has text. Reset is the only control, and it remounts the card.

## How to get to it (user POV)

- `npm run dev`, then open the URL Vite prints.
- `npm run build`.

## Driving it with the terminal

Preconditions:

- Dependencies are installed.

- **Production build.** Run `npm run build`. Vite reports the built files. Exit code `0`. The same build with a base path, `npm run build -- --base=/design-engineering-lab/`, also exits `0`.
- **Dev server.** Run `npm run dev`. Vite prints a local URL. Opening it shows a navigation with the pill links "Blocks", "Tokens", and "Pipeline", and no logo. Blocks is current. The page has three cards. The first is named "Security code". Its open button is "Open Security code details". The dialog's Fill style group has Smooth selected, and Countdown reads 30 seconds with its range input enabled. Choosing Retro disables Countdown and leaves it in the list. Choosing Smooth enables it again. Reset restores Smooth, 30 seconds, and the reels to HELLO!. Arrow keys move the Fill style selection and move focus with it. A click or a tap selects a segment and does not show the focus ring. The reels show HELLO! and the button's accessible name is Create code until it is activated. While the reels move, the same button is greyed out and its name stays Create code. After the code lands its accessible name is Copy code, and after a copy it is Code copied briefly. The button shows no percent and no seconds count. A polite live region announces the new code once when a spin settles. The second card is the hex color picker, starting on Blue 600. Its name "Hex color picker" is not a link or a button. A button labeled "Open Hex color picker details" opens a dialog titled "Hex color picker". The dialog's controls read Radius 80px, Scale 1.15×, and Darken 0.00. Reset sits on the Controls row, its accessible name is "Reset controls", and activating it restores those values. Escape, a click on the dimmed page, or the button labeled "Close" dismisses the dialog and returns focus to "Open Hex color picker details". The card's background does not fade while it moves. At 640px and wider, including 1280×800 and a tablet size such as 820×1180, the panel sits beside the card. Below 640px the feed is one column, the open card is pinned at the top, the panel fills down to the bottom inset, and scrolling the panel body does not move the card, the panel, or the page. Closing restores the scroll position from before the dialog opened. Arrow keys inside the picker move to a neighboring cell, select it, and show the focus ring. A click or a tap selects a cell without that ring; the next Tab lands on the selected cell. Opening a card from a pointer does not draw a ring on the dialog title. The next Tab does draw a ring on the following control. The third card is named "Guide feedback". Its open button is "Open Guide feedback details". The dialog description is "How clear was this guide? Rate it from 1 to 5, then optionally say why and leave a comment." Reset sits on the Controls row, its accessible name is "Reset controls", and activating it remounts the card at the empty scale. The scale is a radiogroup labeled "How clear was this guide?". Each choice is named like "3 of 5, Okay". The word under the scale is hidden from assistive technology. Arrow keys, Home, End, and 1 through 5 select a score immediately. A pointer selection fills toward that score and opens the reasons. The reasons and Add a comment appear together. Add a comment reveals the field and moves focus into it. The field is optional, limited to 280 characters, and submits with Command or Control and Enter. A comment past 280 leaves the counter quiet and marks Submit aria-disabled until the field blurs or a send is attempted, which shows "Too long to send" and returns focus to the field. Dropping back to 280 clears that error. Submit replaces the form with a receipt named "Feedback sent": a check, "Thanks for rating", a one-line summary, and Edit. The summary joins the score, the first selected reason when any are chosen, and "with comment" when the comment has text. A polite live region outside the card says the same summary with commas and that Edit is available for 6 seconds. Edit restores the rating, reasons, and comment and focuses Submit. After 6 seconds Edit leaves the tab order. Cancel and Escape return to the empty scale. Escape leaves the response in place when the comment has text. The Tokens link shows the heading "Camellia Design System", a short line that one token file drives CSS and Figma, and a button labeled "Use dark theme" or "Use light theme". Activating it switches the theme text between "Showing light theme." and "Showing dark theme." The Pipeline link shows the heading "Pipeline" and the sentence "A write-up of the token pipeline will live on this page." Stop the server with Ctrl+C.

## Gotchas

- A successful build proves the app compiles, not that it renders correctly. The showcase behavior tests run against a DOM stand-in, not a browser. The picker model tests do not move the pointer or run the idle timers. One component test clicks a cell center through a scaled border box, including the cell beside a hovered neighbor, in that stand-in. Another checks that a click or a tap selects without focusing the cell, and that arrow keys, Enter, and Space do focus it. The stand-in does not compute `:focus-visible`, so a browser check is what shows the ring stroke.
- The cell focus ring is the `.hex-picker-focus` stroke on `:focus-visible`. The selected cell keeps a separate inner mark. A pointer or touch selection updates the roving tabindex and does not call `focus()`, because Safari paints `:focus-visible` for a scripted focus.
- The picker's card width follows the honeycomb. Readout text that does not fit ends in an ellipsis. The full string stays in the element and in its title.
- Darken starts at 0, so cells near the pointer grow and do not get a brightness filter. Raising Darken sets `--hex-picker-darken`. Radius and Scale set `--hex-picker-radius` and `--hex-picker-scale-hover`. Changing a control while the pointer is over the honeycomb updates the effect without remounting the picker.
- From 640px up the feed uses as many columns as it can, up to three, while every card's content stays at least three quarters of its resting width inside the card's padding. The scale is one factor on the whole component, measured against that padding box, so the component stays inside the padding and does not touch the card edge. When the roomy padding would shrink the component, the card's inline padding tightens from space-6 to space-4. At 744px that is two columns at full size inside the tighter padding. At 820px three columns stay under three quarters even with the tighter padding, so the feed stays at two columns at full size. At 1024px it is three columns, scaled to fit the tighter padding. When the resting component is wider than the padding box, it is taken out of flow and centered so it does not reflow. At 1180px and wider, including 1280px, the component fits inside the roomy padding and the feed is the unscaled three-column layout. Below 640px the feed stays one column and is not scaled. A card's grid height follows the scaled content and does not change when the reels, the fill, or the picker selection change. The feed grid isolates its stacking context, and the sticky bar uses the sticky z-index token, so a raised selected cell cannot paint over the bar on a phone or a tablet. The dialog uses the modal z-index and stays above the bar.
- Opening a card reserves the grid slot at the card's resting height, so the other cards stay put. The open and close moves start from the feed's scale, so a scaled card does not jump to full size on the first frame. The dialog title is focused without a visible ring. Real controls still show a ring for `:focus-visible`. Every open card uses one shared size derived from the viewport. The component inside scales evenly and stays centered. From 640px up the panel stays beside the card, and the card frame shrinks to fit while the panel keeps its minimum width. Below 640px that size is the full width inside the page gutter and about 46% of the usable height. The breakpoint is the existing 640px token. A viewport of exactly 640px is the desktop layout, not the phone layout. Pointer type, hover, and the user agent do not choose the layout. A coarse pointer still shows the card name and open button, keeps the 44px target, and uses the touch slider.
- The name on the card is plain text with `aria-hidden`. The open button's label includes the name. The name and the button appear on hover or focus, and they stay visible when the device has no hover. The open button's tap target stays at least 44px.
- Phone scroll lock is `position: fixed` on the body plus `overflow: hidden` on the root. Headless Chrome does not rubber-band, so a desktop check cannot prove the iOS edge. Safe-area insets are zero in headless Chrome. Below 640px the panel title and Close stay outside the scroller. The description and the controls scroll together in that scroller, with `overscroll-behavior: contain`. A fade under the title, `space-5` tall, uses the surface color and appears only after the scroller has moved. The scroller's end padding is the larger of `space-5` and the bottom safe-area inset. From 640px up the whole panel, title included, still scrolls as one piece. Closing puts the scroll back only after the root has been laid out without that fixed body, and scroll anchoring stays off through that pass. Otherwise Chrome leaves the page at the top or shifts it. The card's close move stays filled until the dialog is removed. Cancelling it while the dialog is still up paints the expanded card for one frame.
- `scripts/demo/check-close-frames.mjs` samples that close in headless Chrome. It needs a running dev server URL and fails if the card jumps back to the expanded frame, or if a scrolled page does not return to the same offset.
- Reset has no filled surface at rest. Hover, focus, and active use the secondary surface as a pill. The global button style is blue, and this control overrides it. On a coarse pointer the range input ignores hits so a horizontal finger drag can move the value; the input stays in the accessibility tree for the keyboard and screen readers. A mouse still uses the range input. Fill style uses the same quiet treatment. It is a radiogroup. Arrow keys, Home, and End move the checked segment and call `focus()`. A pointer selection calls `preventDefault()` and does not call `focus()`, because Safari paints `:focus-visible` for a scripted focus. On a coarse pointer each segment is at least 44px.
- The security-code button fill is the countdown, and a full fill covers the button's border box. The stroke is an inset shadow, so the fill and the rounded ends share one edge. Smooth is the default: the graphite starts empty when the last reel locks and grows left to right in a straight line until the selected duration ends, then the reels flip back to HELLO!. Retro jumps from empty to full in 6 to 10 steps over 3 seconds, holds, then flips back to HELLO!. The Countdown slider shows that duration. The button does not. While Retro is selected the slider stays visible and disabled, so the Controls list keeps its height. The reel row uses the same resting width as the honeycomb. The button uses the small control size, and it is shorter than one reel. On a coarse pointer an invisible extension makes the hit target a 44px square, centered on the button, without changing that visual size. That hit target stays full size while the visual scales to 0.97 on press and eases back to 1. The greyed button and reduced motion stay at scale 1. The visual keeps a transform layer for its whole life, so the press does not promote it and drop it on release. Each icon keeps a layer for opacity, transform, and filter, and the swap runs in Safari too. Reduced motion fades the icon's opacity only. The card does not grow when the digits, the fill, or the icon change. Reduced motion crossfades the flaps with opacity and does not rotate them, including the return to HELLO!. There is no idle flap motion under reduced motion. The retro steps and the smooth growth stay as they are. There is no sound. Hiding the tab pauses the clock, and returning continues the same cycle. The fill layer stays hidden, and its clip stays empty, whenever a countdown is not running, so the white copy of the icon inside the fill cannot paint over the button.
- `prefers-reduced-motion: reduce` leaves the picker still: no proximity, no press dip, and no breath. If a breath is in progress when reduced motion turns on, the mark eases back to rest over 200ms and then stays still. Otherwise the selected mark is already in its final state. In the showcase, reduced motion snaps the card into place and only fades the scrim and the panel.
- The guide feedback card is the visual surface. Its width is the showcase content box. A pointer rating animates the fill one segment at a time. Keyboard selection fills the chosen segments immediately. The receipt height is the receipt size token. Reduced motion drops movement and blur and keeps opacity changes. The 6 second Edit window stays 6 seconds, and it pauses while the document is hidden. The component tests use a DOM stand-in, so they do not compute hover, hairline media queries, or CSS transitions.
- The theme control lives on the Tokens page. The navigation does not include it. The page still starts from the system's light or dark preference.
- `dist/` is generated and ignored by Git.
- The page reads names from `src/styles/tokens.css`. It does not edit that file.
- The page loads Geist and Geist Mono, so the typography samples use those families even when they are not installed on the machine.
- Grayscale font smoothing is set once on `body`. Safari, Chrome, and Firefox on macOS use it. It does not change text on iPhone, iPad, Windows, or Linux, so a check on Linux cannot show the thinner rendering. The dialog, the nav, and the controls inherit it. Nothing in the demo resets it.
