# Demo app

A developer runs a Vite + React page for the Camellia showcase. Text links at the top switch among Blocks, Tokens, and Pipeline. Blocks is a masonry of components. Each card is the component at its resting size. Hovering or focusing a card shows the component name and a button that opens its details. Below 640px the masonry is a single column of full-width cards, and the details panel is not on the page until a card opens. The details view is a dialog. At 640px and wider the card moves to one shared size and a panel sits beside it. On a tighter desktop or tablet width the card frame scales down to fit, and the panel keeps a readable minimum width. Below 640px the card pins to the top at one shared height, the component scales evenly, and the panel fills the rest of the screen down to the bottom inset. That choice follows the viewport width only. A coarse pointer, a missing hover, or a touch screen does not switch the layout. After it opens, only the Controls list scrolls. The page underneath stays put, including on a phone, and closing restores the previous scroll position. Blocks ships two components: the proximity hex color picker, and a security-code generator with six split-flap reels and a Copy code button whose fill is the countdown. Each Reset control is quiet text on the same row as the Controls heading. Tokens lists the generated custom properties and switches light and dark. Pipeline holds a short placeholder. Typography renders in Geist and Geist Mono, which the page loads. The page is not part of the token pipeline roadmap.

## Sub-features

- `demo-dev` serves the page locally with hot reload.
- `demo-build` produces a production build in the root `dist/`.
- `demo-nav` switches among Blocks, Tokens, and Pipeline from text links.
- `demo-masonry` lays the cards out in equal-width columns. Below 640px there is one column. A card's height is its resting size, and opening one does not reflow the grid.
- `demo-details` opens a component's details from its icon button, traps focus, and closes from Escape, the scrim, or the Close button, returning focus to the button that opened it. At 640px and wider the panel sits beside the card. Below 640px the card stays pinned and only the Controls list scrolls. Closing restores the page scroll.
- `demo-theme` switches the Tokens page between light and dark.
- `demo-picker` shows the proximity hex color picker inside its card. Its details panel has Radius, Scale, and Darken controls. Darken starts at 0. Reset is text on the Controls row and restores those values. On a coarse pointer, a horizontal drag on a slider changes its value and a vertical drag scrolls the list.
- `demo-code` shows the security code. Six reels draw a 6-digit code from `crypto.getRandomValues`. This is a demo, not a one-time password. Fill style is Retro or Smooth. Retro is the default and always runs for 3 seconds, in steps. Smooth drains across Countdown, from 3 to 30 seconds, default 5. Countdown stays in the list and is disabled while Retro is selected. Reset restores Retro and 5 seconds. The button's accessible name stays "Copy code". It shows neither a percent nor a seconds count.

## How to get to it (user POV)

- `npm run dev`, then open the URL Vite prints.
- `npm run build`.

## Driving it with the terminal

Preconditions:

- Dependencies are installed.

- **Production build.** Run `npm run build`. Vite reports the built files. Exit code `0`. The same build with a base path, `npm run build -- --base=/design-engineering-lab/`, also exits `0`.
- **Dev server.** Run `npm run dev`. Vite prints a local URL. Opening it shows a navigation with the text links "Blocks", "Tokens", and "Pipeline", and no logo. Blocks is current. The page has two cards. The first is the hex color picker, starting on Blue 600. Its name "Hex color picker" is not a link or a button. A button labeled "Open Hex color picker details" opens a dialog titled "Hex color picker". The dialog's controls read Radius 80px, Scale 1.15×, and Darken 0.00. Reset sits on the Controls row, its accessible name is "Reset controls", and activating it restores those values. Escape, a click on the dimmed page, or the button labeled "Close" dismisses the dialog and returns focus to "Open Hex color picker details". The card's background does not fade while it moves. At 640px and wider, including 1280×800 and a tablet size such as 820×1180, the panel sits beside the card. Below 640px the feed is one column, the open card is pinned at the top, the panel fills down to the bottom inset, and scrolling the Controls list does not move the card, the panel, or the page. Closing restores the scroll position from before the dialog opened. Arrow keys inside the picker move to a neighboring cell, select it, and show the focus ring. A click or a tap selects a cell without that ring; the next Tab lands on the selected cell. The second card is named "Security code". Its open button is "Open Security code details". The dialog's Fill style group has Retro selected, and Countdown reads 5 seconds with its range input disabled. Choosing Smooth enables Countdown. Choosing Retro disables it again and leaves it in the list. Reset restores Retro and 5 seconds. Arrow keys move the Fill style selection and move focus with it. A click or a tap selects a segment and does not show the focus ring. The Copy code button's accessible name stays "Copy code" while the reels are moving and after they stop. The button shows no percent and no seconds count. A polite live region announces "New code:" once when a spin settles. The Tokens link shows the heading "Camellia Design System", a short line that one token file drives CSS and Figma, and a button labeled "Use dark theme" or "Use light theme". Activating it switches the theme text between "Showing light theme." and "Showing dark theme." The Pipeline link shows the heading "Pipeline" and the sentence "A write-up of the token pipeline will live on this page." Stop the server with Ctrl+C.

## Gotchas

- A successful build proves the app compiles, not that it renders correctly. The showcase behavior tests run against a DOM stand-in, not a browser. The picker model tests do not move the pointer or run the idle timers. One component test clicks a cell center through a scaled border box, including the cell beside a hovered neighbor, in that stand-in. Another checks that a click or a tap selects without focusing the cell, and that arrow keys, Enter, and Space do focus it. The stand-in does not compute `:focus-visible`, so a browser check is what shows the ring stroke.
- The cell focus ring is the `.hex-picker-focus` stroke on `:focus-visible`. The selected cell keeps a separate inner mark. A pointer or touch selection updates the roving tabindex and does not call `focus()`, because Safari paints `:focus-visible` for a scripted focus.
- The picker's card width follows the honeycomb. Readout text that does not fit ends in an ellipsis. The full string stays in the element and in its title.
- Darken starts at 0, so cells near the pointer grow and do not get a brightness filter. Raising Darken sets `--hex-picker-darken`. Radius and Scale set `--hex-picker-radius` and `--hex-picker-scale-hover`. Changing a control while the pointer is over the honeycomb updates the effect without remounting the picker.
- Opening a card reserves the grid slot at the card's resting height, so the other cards stay put. Every open card uses one shared size derived from the viewport. The component inside scales evenly and stays centered. From 640px up the panel stays beside the card, and the card frame shrinks to fit while the panel keeps its minimum width. Below 640px that size is the full width inside the page gutter and about 46% of the usable height. The breakpoint is the existing 640px token. A viewport of exactly 640px is the desktop layout, not the phone layout. Pointer type, hover, and the user agent do not choose the layout. A coarse pointer still shows the card name and open button, keeps the 44px target, and uses the touch slider.
- The name on the card is plain text with `aria-hidden`. The open button's label includes the name. The name and the button appear on hover or focus, and they stay visible when the device has no hover. The open button's tap target stays at least 44px.
- Phone scroll lock is `position: fixed` on the body plus `overflow: hidden` on the root. Headless Chrome does not rubber-band, so a desktop check cannot prove the iOS edge. Safe-area insets are zero in headless Chrome. Closing puts the scroll back only after the root has been laid out without that fixed body, and scroll anchoring stays off through that pass. Otherwise Chrome leaves the page at the top or shifts it. The card's close move stays filled until the dialog is removed. Cancelling it while the dialog is still up paints the expanded card for one frame.
- `scripts/demo/check-close-frames.mjs` samples that close in headless Chrome. It needs a running dev server URL and fails if the card jumps back to the expanded frame, or if a scrolled page does not return to the same offset.
- Reset has no filled surface at rest. Hover, focus, and active use the secondary surface as a pill. The global button style is blue, and this control overrides it. On a coarse pointer the range input ignores hits so a horizontal finger drag can move the value; the input stays in the accessibility tree for the keyboard and screen readers. A mouse still uses the range input. Fill style uses the same quiet treatment. It is a radiogroup. Arrow keys, Home, and End move the checked segment and call `focus()`. A pointer selection calls `preventDefault()` and does not call `focus()`, because Safari paints `:focus-visible` for a scripted focus. On a coarse pointer each segment is at least 44px.
- The security-code button fill is the countdown. Retro jumps from empty to full in 6 to 10 steps over 3 seconds, holds, then spins again. Smooth starts full when the last reel locks and drains in a straight line until the selected duration ends. The Countdown slider shows that duration. The button does not. While Retro is selected the slider stays visible and disabled, so the Controls list keeps its height. The reel row uses the same resting width as the honeycomb. The card does not grow when the digits, the fill, or the "Copied" label change. Reduced motion crossfades the flaps with opacity and does not rotate them. The retro steps and the smooth drain stay as they are. There is no sound. Hiding the tab pauses the clock, and returning continues the same cycle.
- `prefers-reduced-motion: reduce` leaves the picker still: no proximity, no press dip, and no breath. If a breath is in progress when reduced motion turns on, the mark eases back to rest over 200ms and then stays still. Otherwise the selected mark is already in its final state. In the showcase, reduced motion snaps the card into place and only fades the scrim and the panel.
- The theme control lives on the Tokens page. The navigation does not include it. The page still starts from the system's light or dark preference.
- `dist/` is generated and ignored by Git.
- The page reads names from `src/styles/tokens.css`. It does not edit that file.
- The page loads Geist and Geist Mono, so the typography samples use those families even when they are not installed on the machine.
