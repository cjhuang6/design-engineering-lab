# Camellia

Camellia is CJ Huang's design system: quiet structure, with color kept for atmosphere rather than decoration. This repository is the design-engineering lab for it. One authored token file generates CSS custom properties and is synced one way into Figma.

## Pipeline

```text
tokens/camellia.tokens.json   DTCG token source (the only one)
        |
        +---> src/styles/tokens.css    generated CSS custom properties
        |
        +---> Figma variables          local plugin, one way
```

Light and mode-independent tokens land on `:root`. Dark semantic overrides use `[data-theme="dark"]`. Generated CSS and Figma are not sources of truth. When they disagree with the JSON, the JSON wins.

`src/styles/tokens.css` is generated by `npm run tokens:css` and committed. Do not edit it by hand.

## Requirements

`package.json` declares Node.js 22.18 or later (`engines.node` is `>=22.18.0`). `npm test` imports the plugin's `.ts` files with `node --test`, which needs Node's built-in TypeScript stripping. That stripping is on by default in Node 22.18 and later. GitHub Actions runs on Node 24 (`.github/workflows/ci.yml`), which satisfies that range.

Install dependencies with `npm ci`. Do not add packages without an approved change to the manifest and lockfile.

## Demo

`npm run dev` opens a token reference page. It reads the custom properties from the generated CSS and paints each one with that variable: color swatches, spacing, radius, typography, and the other groups in the file. A button sets `data-theme="dark"` so semantic colors switch with the existing dark-mode selector. The page starts from the system's light or dark preference.

The font tokens name Geist and Geist Mono. The demo does not load those font files, so the browser uses the next family in each stack.

## Figma plugin

`npm run figma:build` writes `figma-plugin/dist/code.js` (gitignored). In the Figma desktop app, import `figma-plugin/manifest.json` through Plugins → Development. The browser app cannot load a local plugin.

The menu commands today are:

- Inventory (read-only)
- Sync Primitives — dry run
- Sync Primitives
- Sync Semantic — dry run
- Sync Semantic

`Sync Semantic — dry run` writes nothing. `Sync Semantic` creates or updates the `Semantic` collection. Tests for the plugin run against a fake Figma API. They do not prove behavior inside Figma. The steps for the Mac desktop check are in [the Semantic checklist](.cursor/skills/verify-camellia/features/figma-semantic-sync.md).
